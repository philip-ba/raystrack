# Native shortwave irradiance

Raystrack's optional C++20 library provides batched geometry queries for both
the shortwave transport and the v2 longwave cosine view-factor solver. The
Python package and Grasshopper runtime keep their existing installation paths.

## Build and run

See [Embree setup](native-embree.md) for the CPU SDK and build steps, or
[Vulkan setup](native-vulkan.md) for the hardware ray-query backend. Enable both
`RAYSTRACK_EMBREE` and `RAYSTRACK_VULKAN` in the same CMake build to use both
backends. Set `RAYSTRACK_NATIVE_LIBRARY` to the resulting DLL or shared library.
The optional native build always includes a reference CPU BVH, selectable as
`native-builtin`.

```powershell
python examples/ex07_shortwave.py --backend embree
python examples/ex07_shortwave.py --backend vulkan-rt
```

The example computes an annual direct exposure and solves two shortwave steps
with diffuse sky and two surface interactions. It repeats the detailed solve
after moving a shade and changing panel transmittance. All forcing is synthetic.

## Python interface

```python
from raystrack import Scene
from raystrack.shortwave import ShortwaveSolver, SolarSite, SolarTimeline

timeline = SolarTimeline.for_year(
    2026, SolarSite(52.52, 13.405), step_minutes=60, utc_offset_minutes=60,
)
with ShortwaveSolver(Scene(), backend="embree") as solver:
    result = solver.solve(
        [0, 0, 0], [0, 0, 1], timeline, dni=800, samples=0, bounces=0,
        forcing_id="synthetic constant DNI at sun-up",
    )
print(result.exposure()[0, 0, 0])  # sensor 0, direct, neutral channel in Wh/m²
```

Points and normals are oriented free-space sensors in scene coordinates. The
solar provider uses geometric NOAA/Meeus positions. Local standard time defines
the annual interval, with a fixed UTC offset and UTC midpoint timestamps.
World +Z is up and +Y is north at zero north rotation. A caller can also pass
precomputed world-space sun directions and interval durations. The modeled
sun is directional and contributes when its center is above the horizon.

Supply measured or synthetic DNI in W/m² and either DHI for isotropic diffuse
sky or a `PatchSky` / `PatchSkySeries` with radiance in W/(m² sr). The
lower hemisphere is black. The reference Perez import uses an ASCII matrix
generated by `gendaymtx -s -O1 -m N -c 1 1 1`. Load it with
`load_radiance_diffuse_sky(path, ReinhartSkyBasis(N, north_deg=...))` and
align the resulting series with the solar steps. This imports the diffuse upper sky
and leaves the direct sun in the separate DNI input. The Reinhart basis is
independent of the legacy longwave patch indexing.

`ShortwaveResult.irradiance` is an immutable array with axes timestep, sensor,
component and RGB. Components are direct sunlight, sky on primary miss, and
paths whose first surface interaction is reflection or transmission. Each
value is in W/m². `result.total` sums components and `result.exposure()`
integrates the components in Wh/m². Neutral RGB channels each represent the same
quantity. For colored forcing or coefficients, supply a `channel_basis` label
describing the radiometric convention used by those inputs. To estimate
sampling standard error per component, request independent replicates.

## Materials and mutable scenes

- `Opaque(front, back=None)` defines Lambertian reflectance on each mesh
  winding side. `ThinDiffuse(reflectance, transmittance)` describes one
  symmetric, direction-changing diffuse sheet. Coefficients are dimensionless,
  with per-channel reflectance plus transmittance at most one. Unassigned
  surfaces are black opaque.
- `DiffuseSheet(front_reflectance, back_reflectance, transmittance)` adds sided
  reflection with reciprocal shared transmission. `ClearGlazing(index)` models
  a lossless zero-thickness parallel plate in air with discrete reflection and
  straight-through transmission. It connects direct and reflected sun through
  glass chains, including mixed finite scattering paths. See the
  [BSDF coverage and limits](native-bsdf-20261111.md); this is not solid refraction.
- `SolidDielectric(refractive_index=1.52, absorption=0)` instead assigns a
  smooth, finite-volume air/glass boundary to one closed, connected, convex,
  outward-wound mesh. Geometry is in metres; absorption is a Beer coefficient
  in m^-1 (scalar or explicitly labeled RGB). Each interface applies Snell
  refraction, unpolarized Fresnel reflection/transmission and total internal
  reflection. Interior segments attenuate by `exp(-absorption * length)`.
  Reverse radiance transmission includes `(eta_current/eta_next)^2`; these
  factors cancel for an air-to-air slab. Every boundary consumes one interaction.
  This slice accepts **sky forcing only** (`dni=0` for every step/channel),
  including finite scattering and clear plates outside the solid. Direct sun
  through refracting solids needs a separately validated connection estimator
  and is rejected even when a particular sensor would miss the solid.
  See [current coverage and evidence](native-glass-urban-20261111.md).
  The supported index interval is [1, 10], bounded for float ray angular
  precision. Normal ray offsets perturb the path by epsilon; the omitted
  distance to the previous boundary plane is restored for Beer absorption.
  This approaches the unshifted path as the offset shrinks. Poorly conditioned
  slender boundary facets can still defeat hardware intersections; detected
  inconsistent medium crossings fail explicitly.
- `KlemsBSDF.from_xml(path, band="solar", window_front="front")` imports
  Full Klems BRDF and BTDF data from WINDOW XML. The loader supports separate
  front and back lobes and can bind WINDOW Front to either winding side. The
  material frame projects mesh-local +X into the hit plane and uses +Y as a
  fallback. The Python object can also inspect Visible data. The shortwave
  transport accepts the Solar band. Klems evaluation and reverse importance
  sampling use the projected patch areas and the matrix's incident/outgoing
  ordering.
- `scene.update_transform`, `update_vertices`, and `update_mesh` edit geometry.
  `solver.set_material(surface_id, material)` changes only the optical
  assignment, preserving the acceleration structure. Removing a surface
  retires its assignment even if the same ID is reused later. Each result
  records the geometry and material revisions used by that solve.

The solver supports a fixed maximum path depth per solve and returns a
completed snapshot. It uses batched intersections and shadow rays, and reduces
sky transfer by patch before applying the timestep radiances. It supports
diffuse reflection/transmission and tabulated finite-width Klems scattering.
Clear-plate delta events are supported with explicit image/branch capability
limits. Solid dielectric sky transport is limited to exterior sensors and
disjoint bounding boxes between each solid and every other surface. Nesting,
overlaps, interior objects, nonconvex or open solids are rejected; bounding-box
exclusion can reject physically disjoint shapes. Validation is limited to 100
million face/vertex plane checks per solid. Thickness and clearances must exceed
the ray offset and float geometry resolution; unresolved geometry raises a
capability error. Polarization state, coherent interference, dispersion within
a band, and volumetric scattering are unsupported. Each smooth boundary uses
scalar unpolarized Fresnel coefficients; repeated oblique boundaries do not
track polarization correlations. The material interface requires native ABI 4;
older libraries fail before any scene call.

Explicit independent wavelength intervals are available through
`WavelengthBand`, `BandInput` and `solve_independent_bands`. Supply complete
per-band scalar optics and band-integrated forcing, with provenance. See the
[band contract and runnable example](native-wavelength-bands.md). RGB channels
and separate Solar/Visible matrices do not constitute spectral input.

The [annual urban workflow](annual-urban.md) adds bounded time blocks,
checkpoint/restart, scheduled scene edits and a staged scale sweep. It wraps
completed native solves rather than resuming an in-flight native path budget.

## Longwave and performance

Use `Solver(scene, device="embree")` or `device="vulkan-rt"` to select native
traversal for the existing longwave cosine estimator. The Python v2 solver
still owns run scheduling, ray generation, uncertainty and result snapshots.
Its `device="vulkan"` setting continues to select Taichi Vulkan compute. The
area-pair estimator retains its existing CPU path.

Native closest-hit ties on exactly coincident triangles are backend-dependent.
In a longwave retry past an excluded hit, an eligible hit at the same ray
distance can also be skipped. The validated scenes use distinct geometric
intersections.

The native backends retain geometry for stationary and material-only solves.
Embree updates changed vertex buffers and refits fixed-topology geometry;
topology changes and a periodic refresh rebuild its traversal. Vulkan rebuilds
BLAS/TLAS after edits while retaining its device, pipeline and mapped ray buffers.
Both paths still consume flat world-space geometry. Vulkan runs
traversal on the device with batched transfers. Ray generation and reductions
still run on the host. The [Vulkan benchmarks](native-vulkan.md#shortwave-benchmark)
show the difference between a usable hardware backend and a workload that
benefits from it. Shared native prototypes, transform-only TLAS updates and
GPU-resident transport remain performance milestones. OptiX requires a supported
NVIDIA test machine. The [annual reference workflow](../validation/annual-radiance.md)
defines the cube fixture, separate sun/sky coefficients and acceptance gates.
The [licensed measured-product Solar fixture](measured-bsdf-reference.md) adds
unchanged CGDB data, side-specific integral checks and explicit reciprocity
residuals. The [current capability matrix](native-glass-urban-20261111.md)
distinguishes verified paths from limits and unsupported combinations.

For controlled diffuse and directional Klems panel comparisons, run:

```powershell
.local/release-venv/Scripts/python.exe validation/validate_shortwave_panels.py
```

This adds a finite overhead panel to the cube at selected sun directions and
also checks large-sheet analytic limits and off-axis sensors. Outputs and every
Radiance command go to `build/annual-validation/panels/`. A distinct Solar/Visible
XML probe identifies the installed Radiance block selection: the tested 5.4
build evaluates Visible coefficients. The comparison deliberately duplicates
Solar coefficients into Visible and labels this controlled equivalence; it does
not establish Radiance support for the Solar block. The
[new glazing validation](native-bsdf-20261111.md) checks actual native delta
transport against the analytic plate and pinned Radiance.
